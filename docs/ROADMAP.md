# 演进路线

FinScope 当前版本把「确认式跨会话 Memory、确定性计算、硬约束匹配、带来源的条款问答」四项能力做成了可复现的完整链路。本文记录下一步的演进方向，按投入产出排序。

## 检索层：从词项检索到混合检索

当前 `catalog.py` 的检索阶段执行**生效日期过滤 + 词项/字符匹配**，命中排序按词项重合度并让子串完全命中优先，返回携带 `term_id`、版本与生效区间的条款。

演进方向：

1. **引入稠密向量召回**，与词项检索并行，覆盖中文同义改写场景。
2. **加权 RRF 融合**（`k=60`，权重走配置而非模块常量），使召回结果可解释、可调参。
3. **交叉编码器重排**，对融合后的候选做精排。
4. **阶段消融与指标报告**：输出 Recall@1/3/5、MRR、nDCG、延迟 P50/P95 与 bootstrap 95% 置信区间，并按查询类型（精确 / 改写 × 中 / 英）分组。未安装的后端标记为 `skipped`，不以词法分数替代混合检索增益。
5. **检索状态工具化**：新增 `retrieval_status` 类工具，使调用方在引用条款前可读取实际生效的检索阶段。

## 编排层：从单路径编排到工具自主选择

当前分析主线是一条确定性编排：读取确认画像 → 抽取字段 → 计算 → 匹配 → 检索，每一步的工具由业务规则固定选择，轨迹逐步落盘，可完整回放。

演进方向：

1. **计划与执行分段**：把编排显式拆为 `plan()` 与 `execute(steps)` 两段，计划步骤列表化为可审计产物，便于在计划层做变更与对照。
2. **条款问答路径支持模型自主选择工具**：在保留确定性路径作为基线的前提下，为问答路径提供工具调用循环（含最大回合与最大工具调用数上限），使模型可自行决定检索轮次与是否需要读取画像，并输出完整工具轨迹。
3. **策略对照评测**：同一批输入下比较「模型自主选择工具」与「固定检索路径」的质量、工具调用次数、耗时与 token 用量，共用模型、输入、输出结构与校验器。

## 评测层：补记忆方案对照

当前实现只有一种记忆形态——用户确认的结构化画像。演进方向是补齐与另两种方案的对照实验，比较「无跨会话记忆」「最近若干轮对话历史」「已确认结构化画像」在偏好更新正确率、跨用户隔离、删除后残留、耗时与 token 用量上的差异。数据规模、标签来源与运行配置逐项记录，评测集与标签分文件存放，避免按答案调参。

## 模型层：真实服务接入后的评测集

接入真实模型服务后，建立带人工标签的中文字段抽取集与条款问答集，逐项记录模型名、配置、失败率、延迟与 token 用量，并按 `query_kind` 与场景分组报告。

## 服务层：多用户与可观测性

面向多用户部署时替换数据后端、补充限流与访问审计、串联结构化日志与指标，并把轮询式任务状态推进为带进度回报的异步任务接口。

## 数据与领域扩展

- 条款库替换为自有语料（保持 `catalog.json` 字段结构即可迁移）。
- 扩充产品类型与约束维度，例如费用结构细分、目标类型扩展。
- 补充更多评估序列，覆盖跨会话连续更新与多目标任务。
