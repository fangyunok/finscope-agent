# 项目描述与演示要点

## 项目名称

**FinScope：用户画像与金融需求分析平台**  
Python · MCP · SQLite · Pydantic · Decimal · Starlette

## 可核实的简历描述

> 开发用户画像驱动的金融需求分析平台，以用户确认的结构化 Memory 管理跨会话资料，通过 MCP 调用确定性收支计算、模拟产品硬约束过滤与版本化条款检索；实现画像提议与确认、来源追踪、版本冲突控制、用户隔离及删除后并发写回阻断，并使用独立模拟序列验证跨会话更新与计算行为。

验证数据：本地 Windows / Python 3.12 **100 项测试通过**；**20 组模拟跨会话序列通过**，执行 83 次实际 MCP 工具调用，模型调用为 0。该数据验证工程行为与合成场景，不代表真实模型准确率或投资效果。

项目使用合成用户与产品数据。可选模型适配器提供字段抽取和带引用的条款回答；真实 Qwen 验证完成前，不写“模型问答准确率”“真实金融推荐效果”或“生产服务上线”。规则评分不是训练的推荐模型。

## 五分钟展示

1. 选择 Alice，核对示例资料并确认；展示程序计算出的 1,500 元月结余、7,000 元差额和 5 个完整月份。
2. 查看模拟产品候选与排除原因，指向流动性、风险与锁定期约束及对应条款。
3. 再次分析，说明当前资料来自已经确认的持久化画像。调整目标期限为 3 个月，展示提议差异和确认后的新版本。
4. 切换另一用户，说明资料和分析不能互读。收藏产品后，展示风险偏好保持原值。
5. 删除 Alice 的记忆，再次分析要求补资料，旧运行 ID 不可访问。展示测试和模拟序列报告。

## 关键设计问题

- 短期对话上下文与确认的长期画像有什么区别，为什么写入需要人工确认。
- 版本和记忆代次分别解决什么问题，删除如何阻止已经在执行的请求写回。
- 兴趣反馈为什么不能视为风险承受能力。
- Decimal 运算、单位和舍入规则如何让金额可以检查；为什么不让模型输出计算结果。
- 硬约束先于排序；规则分数如何解释，没有标签时为什么不声称推荐质量。
- 词项检索与向量检索的区别，引用结构核验与语义支持核验的区别。
- 离线协议测试、模拟评测、真实模型评测各能证明什么。
